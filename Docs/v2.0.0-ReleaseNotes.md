# v2.0.0 Release Notes

Rebuilt from the ground up as **one native Windows exe**: `ServerDocumentationTool.exe`. The PowerShell engine, the Engine folder and the separate updater are gone. Built on v1.1.0; the report is the same document.

## Install (once by hand when coming from v1.x)
v1.x cannot update itself to v2.0.0, because a release is now a single exe instead of a ZIP.
1. Download `ServerDocumentationTool.exe` (and `ServerDocumentationTool.exe.sha256`) from Releases.
2. Right-click the exe, **Properties**, tick **Unblock**.
3. Put it in a writable folder, for example `C:\Tools\ServerDocumentationTool`, and run it.
4. The old v1.x folder (`InfrastructureAsBuiltBuilder.exe`, `IABB.Updater.exe`, `Engine\`) can be deleted.

From v2.0.0 on, **Check for Updates** and **Update from File...** replace the exe in place.

## What changed for the targets
- **No WinRM needed.** Everything is read over WMI (DCOM), the Remote Registry service, the admin share, LDAP and the DHCP Server API. Servers where WinRM was refused or slow (four servers in the v1.0.2 field test) should now be **Complete** instead of Partial, as long as WMI is allowed.
- **No RSAT or PowerShell modules needed,** on the targets or on the PC running the tool.
- Local accounts, applications, certificates, IIS and SQL are now collected on DCOM-only servers (in v1.x they showed "Not collected").
- Firewall needed per target: WMI/RPC (TCP 135 + dynamic RPC), SMB (TCP 445), LDAP (TCP 389) on domain controllers.

## How each section is collected now
- **Hardware, OS, disks, network, services, hotfixes, shares, printers, page file, environment, local users and groups:** WMI (same classes as before); group members through ADSI.
- **Roles and features:** WMI `Win32_ServerFeature` (works over DCOM). The table lists display names; DFS Namespaces, DFS Replication and RD Session Host keep their short names for role detection.
- **Applications, SQL instances, IIS version:** the registry, through the Remote Registry service; if that service is not available, through WMI (slower, same data, noted in the warnings).
- **Certificates:** local store for the server running the tool; for other servers the certificate store in the registry.
- **IIS:** `applicationHost.config` read through the admin share. Site and pool state comes from the IIS WMI provider when it is installed, otherwise it shows **Unknown**.
- **AD DS:** LDAP directly to the domain controller ("Collected Via: LDAP to the domain controller").
- **DNS:** the DNS WMI provider, hard 120 s limit (as in v1.1.0).
- **DHCP:** the DHCP Server API ("Collected Via: DHCP Server management API (RPC)").

## Unchanged
- The report: same sections, order, texts, tables and rules. Proven by rendering the 153 RawData files of the v1.0.2 field run with the new code: every DOCX matches the PowerShell output byte for byte (apart from the Generated line and the version).
- Role detection: same results as v1.x on all 139 collected servers of that run.
- Status rules (Complete / Partial / Failed, zero-row rule), time limits per step and per server, parallel servers, Cancel, Discover Domain skip rules, Test Reachability.
- RawData JSON: same field names (`SchemaVersion` 2.0.0).

## New
- **Settings file:** `%ProgramData%\ServerDocumentationTool\appsettings.json`, created on first start; **Open Settings** opens it. Renamed keys: `CimOperationTimeoutSec` is now `WmiQueryTimeoutSec`, `TimeoutSeconds` is now `ConnectTimeoutSec`; `EnableDcomFallback` is gone (DCOM is the only transport). New: `DefaultClientName`.
- **Rebuild reports from RawData:** `ServerDocumentationTool.exe --render <RawData folder> <output folder> [client name]` (also reads v1.x JSON).
- Run log renamed to `ServerDocumentation_Run.log`.
- Every WMI query, registry connection and group-member lookup has a hard time limit, so one hung call cannot hold up a step.

## Removed
- PowerShell engine, legacy PowerShell launcher, `IABB.Updater.exe`, Engine folder, "Enable DCOM fallback" option.
- The v1.x code is kept in the repository under `legacy/powershell-engine-v1.1.0` for reference only.

## Validation
- Built and tested here with Mono (compile of every source file; report replay of 153 field servers; 68 unit tests of the collector logic). **Nothing was run on Windows here.**
- GitHub Actions builds the exe, runs the unit tests, installs the DNS, DHCP and IIS roles on the build machine and runs the app's self-test, which collects the build machine and checks the DNS zone and forwarder, the DHCP scope and the IIS site. Tag only after this build is green.
