# v1.0.1 Release Notes: renamed to Server Documentation Tool

Built on v1.0.0. Fixes the v1.0.0 start-up failure and renames the product; collection and report content are unchanged. This is also the first release the v1.0.0 update button can install. The v1.0.0 update check works even though its engine fails to load.

## Fixed
- **v1.0.0 could not start its engine:** "The PowerShell engine could not be loaded: Cannot process argument because the value of argument 'host' is null."
  - Cause: the runspace pool was created with an overload that does not accept an empty host.
  - Fix: the pool is now created from the session state and then sized (`EngineHost`).
  - The PowerShell-only smoke test could not catch this, because it never ran the app's C# code.
- **New app self-test:** `InfrastructureAsBuiltBuilder.exe --selftest <folder>` loads the engine exactly as the app does, collects the local machine through the app's own runner, and writes the JSON, DOCX, HTML and `selftest.log`. GitHub Actions now runs it after every build, so a release cannot ship if the app's own code path fails.

## Changed
- **Product name:** "Infrastructure As-Built Builder" is now **Server Documentation Tool** everywhere you see it:
  - the window title and heading, and the start-up and run log lines;
  - the DOCX "Generated By" line and the HTML summary;
  - the update dialogs, file properties, GitHub release titles and documentation;
  - the legacy PowerShell launcher window.
- **Document title** in each DOCX and the HTML summary: "Server As-Built Documentation" (was "Infrastructure As-Built Documentation").
- **SYDI wording removed** from the README and roadmap.
- **Default output folder:** `C:\ServerDocumentation` (was `C:\InfrastructureAsBuilt`). When you update, your existing setting is kept. To use the new default, change `DefaultOutputRoot` in `Engine\Config\appsettings.json`, or pick the folder with **Browse...**.
- Settings `AppName` and `DefaultDocTitle`, and the template name, renamed to match.
- The smoke test now reads the expected version from `VERSION.txt`, so version bumps need no test edits.

## Kept on purpose
- File names `InfrastructureAsBuiltBuilder.exe`, `IABB.Updater.exe` and `InfrastructureAsBuiltBuilder_v<ver>.zip`, and the `Engine\Start-InfrastructureAsBuiltBuilder.ps1` launcher. The v1.0.0 updater looks for these names, so renaming them would stop installed copies from updating themselves.
- Internal code names: the `IABB.*` modules and functions. They never appear in reports.

## Unchanged
- All collection, report content and rules from v1.0.0 / v0.9.9i.

## Validation
- Static checks only here; the GitHub Actions build (syntax check, smoke test with a real local collection, compile, package) validates on push.
- **Update test:** with v1.0.0 installed, publish v1.0.1. Start v1.0.0, click **Check for Updates** (or the "Update available" link) and confirm the app restarts as Server Documentation Tool v1.0.1 with your settings kept.
