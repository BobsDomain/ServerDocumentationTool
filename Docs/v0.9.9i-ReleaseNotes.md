# v0.9.9i Release Notes

Built on: v0.9.9h, which was field-tested on 2026-11-17 against a full AD discovery: 153 servers, 135 Complete / 4 Partial (DCOM) / 14 Failed (no ping), 153 DOCX created, 0 invalid, 0 empty tables. Scope approved 2026-11-17 from that test. Fixes only, no new features.

## Changed

### 1. Shorter reports: certificates (field test: 15% of an average report)
- In the test, 94% of certificate rows were Windows' built-in Root/CA certificates (Root 7,758, CA 1,613, My 613 rows).
- The **Certificates** table now lists:
  - certificates in the server's own **Personal (My)** and **Web Hosting** stores;
  - **Root/CA certificates expiring within 60 days**.
- All other Root/CA certificates are counted in the summary ("Built-in Root/CA certificates (not listed)", "Expired legacy roots (informational, not listed)") and stay in the RawData JSON.
- The summary now shows Server Certificates, Expiring Within 60 Days (all stores), Expired (action required), the two not-listed counts, and Unique Certificates (all stores).
- If nothing qualifies, the report says so instead of showing an empty table.

### 2. Shorter reports: Installed Applications (field test: 21.5% of an average report)
- The list now matches **Programs and Features**. Entries marked `SystemComponent=1`, update entries (`ParentKeyName`, `ReleaseType` Update/Hotfix, "Update for…"/"Hotfix for…") are not listed.
- Those entries are kept in the RawData JSON as `Applications.HiddenEntries`, and the summary shows "System Components / Updates (not listed)".
- Install dates are shown as ISO (`2024-03-11`, was `20240311`).
- The zero-row rule counts listed and hidden entries together, so a server with only system components is not marked "No data".

### 3. Print Spooler disabled is no longer a warning (field test: 10 servers)
- Before querying printers, the tool checks the Print Spooler service. If it is stopped, disabled or missing, the Printers section says, for example, "The Print Spooler service is Stopped (Disabled), so no printers are available on this server." No Collection Warning is added.

### 4. Demoted-DC message is now a role note, not a Collection Warning (field test: 2 servers)
- It is shown under **Role Services** as "Note: AD DS role files are still installed (NTDS service Stopped / Disabled) but this server is a member server, not a domain controller (DomainRole 3). It was probably a domain controller that has been demoted."
- Stored as `RoleNotes` in the RawData JSON.

### 5. Role detection (field test: 9 "General Purpose" servers were file, print and DFS servers)
New roles, each listed with its service under Role Services:
- **File Server**: non-administrative disk shares (excluding `x$`, SYSVOL, NETLOGON) **and no other workload role** (DFS roles excepted). In the field test, 100 of 139 servers had at least one share (backup, audit, client shares), so shares alone would have labelled almost every server. Replayed on the field data, this rule labels exactly the 6 former "General Purpose" servers that serve shares; the 3 without shares stay General Purpose. Service: LanmanServer.
- **Print Server**: one or more shared printers (22 servers in the field data). Service: Spooler.
- **DFS Namespace Server**: FS-DFS-Namespace installed (non-DC). If features weren't collected, the running Dfs service is used instead. Service: Dfs.
- **DFS Replication Server**: FS-DFS-Replication installed (non-DC). If features weren't collected, the running DFSR service is used instead. Service: DFSR.

### 6. Labels
- **Nested Hyper-V** (field test: 2 VMs): a virtual machine running the Hyper-V role now shows **"Hyper-V Host (nested)"**. Platform Classification shows "Hyper-V Host: Nested (virtual machine running Hyper-V)". Physical Hyper-V hosts are unchanged ("Hyper-V Host", Physical).
- **Azure** (field test: 1 VM): detected from the Azure SMBIOS asset tag (`Win32_SystemEnclosure`). Host Platform shows "Azure" and Virtualization Platform shows "Microsoft Azure". `Get-IABBPlatformInfo` gained an optional `-AssetTag` parameter.

## Not included (not approved)
- Discovery filter for disabled/stale computer accounts. This waits for the owner to confirm whether the 14 unreachable servers are decommissioned.

## Changed files
- Code: Collector.Applications, Collector.Server, RoleDetection, DocumentBuilder, Core (schema version only).
- All other modules: version header only.
- Start script, Config, Template, VERSION.txt, README, Docs.

## Unchanged (regression guard)
- Everything from v0.9.9h:
  - AD DS/DNS/DHCP from the target with credentials;
  - per-server isolation;
  - XML-safe text;
  - "Not collected" instead of empty tables, zero-row rule, mismatch row;
  - IIS bindings;
  - run log.
- Exported `New-IABBHtmlSummary`, `New-IABBOpenXmlDocx`; fixed column-grid tables; WSMan -> DCOM fallback; Collection Status banner; Hyper-V host = physical.
- Removed on purpose and still removed: Scheduled Tasks, AD DS DC/FSMO tables, DNS zone table.

## Validation
- Static checks only. **Not executed on Windows.**
- The new certificate and role rules were replayed (in Python) against the v0.9.9h field-test RawData:
  - certificate rows listed drop from 9,025 to 674 (93% fewer), and every server still lists at least one certificate;
  - roles: File Server 6, Print Server 22, DFS Namespace 4, DFS Replication 3.
- Suggested field test: re-run the same client.
  - Report sizes should drop noticeably.
  - Spooler-disabled servers should show the note and no warning.
  - The former "General Purpose" servers should show File / Print / DFS roles.
  - The two nested Hyper-V VMs and the Azure VM should show their new labels.
