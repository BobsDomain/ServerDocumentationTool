# v1.1.0 Release Notes

Built on v1.0.3. Fixes the three open items from the v1.0.2 field test (2026-11-17, 153 servers in 34.5 minutes).

## New: Update from File... (servers without internet)
- New button **Update from File...** next to Check for Updates.
- Steps:
  1. On a PC with internet, download both release files: `InfrastructureAsBuiltBuilder_v<version>.zip` and `...zip.sha256`.
  2. Copy them **together** to the server.
  3. Click **Update from File...** and choose the ZIP.
- The app checks the file name and the SHA256 checksum, says whether the version is newer, the same or older, and asks before installing. It then updates through the same updater as the online button: it closes, replaces its files, keeps your `Engine\Config\appsettings.json`, and restarts.
- A ZIP without its `.sha256` file, or with a wrong checksum, is refused and nothing changes.

## Fixed: DNS step running into the 300 s limit (one domain controller in the field test)
- Zones and forwarders are now read from the DNS Server's WMI provider (`root\MicrosoftDNS`, classes `MicrosoftDNS_Zone` / `MicrosoftDNS_Server`). **Every query has a hard 120 s limit.**
- If the DNS service does not answer, the step now fails in about 2 minutes, not 5. The report states the reason: "The DNS Server did not answer the zone query within 120 seconds (DNS WMI provider not responding)".
- The DnsServer PowerShell cmdlets are only a fallback when the WMI provider is unavailable. They are not used after a timeout, because they would hang the same way.
- The WMI provider needs no DnsServer module (RSAT) on the target or on this PC, and works over WinRM, DCOM and locally.
- Report content is unchanged: zone counts, reverse, AD-integrated, forwarders. The RawData JSON now records `Source` (which method was used).
- The build tests this for real: the GitHub runner installs the DNS Server role with a test zone and forwarder, and the smoke test checks that both are read through the WMI provider.

## Fixed: unreachable servers from Discover Domain
- **Discover Domain** no longer adds computer objects that are not live servers:
  - **disabled** computer accounts;
  - **failover cluster name objects** (CNO/VCO), which are not servers;
  - accounts with **no logon to the domain for more than 90 days** (`lastLogonTimestamp`).
- Every skipped object is written to the log with its reason and last logon date, for example "Skipped X: No logon to the domain for more than 90 days (last logon: 2025-06-02)". Nothing is hidden.
- The 90-day limit is set by `DiscoveryStaleDays` in `Engine\Config\appsettings.json`; `0` turns the stale-account filter off.
- Servers added by name or from a file are never filtered.
- The legacy PowerShell launcher applies the same rules.

## Other
- The "N server(s) queued" label no longer repeats the time limits. They are still in the run log header.
- Version 1.1.0 throughout (DOCX, HTML, JSON SchemaVersion, file properties).

## Unchanged
- Collection, report content and rules from v1.0.3; online update button; self-test.

## Validation
- Static checks only here. GitHub Actions now also runs the DNS collector against a real DNS Server on the build machine (zone `ci.test`, forwarder `192.0.2.53`), as well as the smoke test, compile and app self-test.
- Field test:
  - run Discover Domain on the client and check the "Skipped" lines (the 13-14 unreachable servers should be among them, or stay as Failed);
  - check the DNS result for the domain controller whose DNS step timed out;
  - install with **Update from File...** on the offline server.
