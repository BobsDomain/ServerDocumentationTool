# v2.0.1 Release Notes

Fixes only, from the v2.0.0 field test (2026-11-24, 139 servers: 99 Complete, 40 Partial, 0 Failed, 2 h 10 min). Built on v2.0.0. Install it with **Check for Updates** or **Update from File...** (`ServerDocumentationTool.exe` + `ServerDocumentationTool.exe.sha256`).

## Fixed: applications step timing out (34 servers) and the long run time
- The registry is now read by the app's own reader instead of the .NET registry class:
  - only the values the report uses are read (7 per installed program), one network call each; v2.0.0 read every value of every program with about three calls per value;
  - a program entry without a display name is skipped after one call;
  - 8 entries are read at the same time per server (4 for the local server and the WMI registry provider).
- In v2.0.0 the step took a median of 86 s (v1.0.2 on WinRM: under 1 s) and 34 servers reached the 300 s limit. Expected now: a few seconds per server, and the whole run back near the v1.0.2 time.
- Certificates and SQL Server use the same reader.

## Fixed: certificates "No data" (5 servers)
- A registry read that fails now reports the real Windows error (for example "Access is denied (error 5)") instead of looking like an empty key. A dropped Remote Registry connection is reopened once.
- When the Remote Registry service returns no certificates at all (a server always has Root certificates), they are read again through the WMI registry provider, and the warnings say so.

## Fixed: old expired certificates listed
- Certificates replaced by a renewal are kept by Windows as "archived" and hidden from the certificate store. Reading the registry showed them (about 230 extra EXPIRED entries, mostly on domain controllers). They are now left out, as in v1.x.

## Fixed: local accounts step slow or timing out
- Group members are looked up 6 groups at a time (v2.0.0: one at a time; median 36 s, up to 300 s). Each group has its own 60 s limit.
- Local members are shown as `user` again, not `SERVER\user` (as in v1.x).
- **Any step that reaches its time limit now keeps the data it had already collected**, with the warning "Data collected before the time limit is shown". In v2.0.0 one domain controller lost its printers, groups, page file and environment variables this way.

## Fixed: printers on print servers
- `Win32_Printer` is slow over DCOM on servers with many print queues. After 60 s the printer list is read from the spooler's registry key instead (name, driver, port, shared, share name, location), with a note in the warnings.

## Fixed: IIS
- Site and application pool state on servers without the IIS WMI provider (53 of 123 sites showed "Unknown") now comes from the IIS performance counters, which exist wherever IIS is installed. "Unknown" remains only when neither is available. **Please check a few IIS servers in the field.**
- Application pools are listed by name again (as in v1.x and IIS Manager).

## Fixed: Discover Domain skip list in the run log
- The skip list (with the reason for each computer object) was only shown in the window, because discovery runs before the run folder exists. It is now also written to `ServerDocumentation_Run.log` when the run starts.

## Build
- The GitHub build now also starts the Remote Registry service on the build machine and has the self-test read the machine through it. The self-test checks that applications match the local read, that the Personal certificates match the certificate store, and that a missing key reads as empty rather than as an error. This tests the code path used for every remote server.

## Unchanged
- Report layout and rules; collection steps and status rules; settings file and keys; JSON fields (`SchemaVersion` 2.0.1).

## Validation
- Here: compiled with Mono, 89 unit tests, report replay of the 153 v1.0.2 field servers (DOCX identical to v2.0.0/v1.x output apart from version lines). **Nothing was run on Windows here.**
- GitHub Actions: build, unit tests, DNS/DHCP/IIS role fixtures, self-test including the Remote Registry check.
- Field test: run the same servers and compare with the v2.0.0 run (99/40/0, 2 h 10 min): run time, Partial count, the 5 certificate servers, the print servers, IIS state, and the skip list in the run log.
